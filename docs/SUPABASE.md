# Подключение Supabase

Система хранит данные в PostgreSQL. Supabase — это PostgreSQL в облаке, поэтому подключение — одна строка
в `.env`. Таблицы, справочники и представления создаются автоматически при запуске.

## Как это работает

- **Основная база — Supabase.** Всё, что вносят сотрудники, сохраняется туда.
- **Локальная база — зеркало.** Пока Supabase доступен, каждые `DB_MIRROR_MIN` минут его данные копируются
  в локальную базу (PostgreSQL в `docker compose` или SQLite при запуске без Docker).
- **Supabase пропал** — через 20–40 секунд система сама переходит на зеркало, работа не останавливается.
  Сверху у всех появляется полоса «Supabase недоступен — работаем на локальной базе».
- **Supabase вернулся** — всё, что внесли за время отключения, переносится обратно, работа продолжается в Supabase.
- **Сервер запустился без связи с Supabase** — работаем на локальной базе. Когда Supabase ответит, администратор
  решает в «Данные → База данных»: вернуться с переносом локальных данных или без.

Состояние видно в разделе **«Данные → База данных»**: где сейчас данные, есть ли связь, когда обновлялось зеркало.

## Подключение за 5 минут

1. Создайте проект на [supabase.com](https://supabase.com) (регион поближе — например, Frankfurt). Запомните пароль базы.
2. Откройте **Project Settings → Database → Connection string → URI** и выберите режим **Session pooler** (порт `5432`).
   Скопируйте строку и подставьте пароль вместо `[YOUR-PASSWORD]`.
3. Добавьте строку в `.env` рядом с `docker-compose.yml`:

   ```bash
   SUPABASE_DB_URL=postgresql://postgres.abcdefghijkl:ПАРОЛЬ@aws-0-eu-central-1.pooler.supabase.com:5432/postgres
   ```

4. Перезапустите: `docker compose up -d --build`.
5. Проверьте: «Данные → База данных» должна показать **«Supabase — основная база»**.

> Режим **Transaction pooler** (порт `6543`) тоже работает. Прямое подключение (`db.<ref>.supabase.co`) требует IPv6 —
> если сеть его не поддерживает, используйте Session pooler.

## Перенести уже внесённые данные в Supabase

Если вы уже работали на локальной базе и хотите взять эти данные в Supabase:

1. **До подключения Supabase:** «Данные → Набор данных → Скачать dataset.json».
2. Подключите Supabase (шаги выше). В пустой Supabase при первом запуске загрузятся демо-данные.
3. «Данные → Набор данных → Загрузить» — выберите сохранённый `dataset.json`.

## Безопасность

- В `.env` хранится только строка подключения к базе — ключи `anon` и `service_role` системе **не нужны**.
  `.env` не попадает в git.
- Supabase по умолчанию открывает таблицы схемы `public` через свой REST API. Система при каждом запуске
  **включает RLS на всех своих таблицах и снимает права у ролей `anon` и `authenticated`** — через REST API
  данные не видны, читать их может только сервер системы.
- SSL включается автоматически (`sslmode=require`).

## Если не подключается

| Сообщение в логе (`docker compose logs backend`) | Что сделать |
|---|---|
| `password authentication failed` | Проверьте пароль базы в строке подключения (не пароль от аккаунта Supabase) |
| `connection timeout` / `Network is unreachable` | Используйте строку **Session pooler**, а не прямое подключение |
| `Supabase недоступен при старте — работаю на локальной базе` | Проверьте интернет и что проект Supabase не на паузе (бесплатные проекты засыпают через неделю без активности) |

## Настройки

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `SUPABASE_DB_URL` | пусто | Строка подключения к Supabase. Пусто — работаем только на локальной базе |
| `DB_CHECK_S` | `20` | Как часто проверять связь с Supabase, секунд |
| `DB_MIRROR_MIN` | `5` | Как часто обновлять локальное зеркало, минут |
